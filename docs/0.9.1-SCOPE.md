# 0.9.1 — everything we are building

Set 2026-11-03; statuses re-read from the tree on 2026-11-04 (`origin/testing`, `2dd7e56`,
versionCode 147). This is the complete scope as it stands after the milestone re-alignment
(`docs/MILESTONES.md`, D28). It is a living document: 0.9.1 stays open until the owner signs it,
and it absorbs whatever the acceptance run and real use turn up.

## How to read this

- **In the build** — merged to `testing`, release-signed nightly available. An issue may still be
  open because it closes on the owner's device verification, not on the merge.
- **Device pass outstanding** — built and unit-tested, waiting on a real phone and a live gateway.
- **In flight** — an open pull request, under review. (There are none open as this is written.)
- **Not built** — decided and scoped, no code yet.
- **Carried** — wanted, but not a gate; done here if achievable, otherwise closed wherever it
  closes.
- **Out** — explicitly not this release.

## 1. The loop and its surfaces — in the build

The release's original purpose: a stranger gives a command by voice, sees what is happening, gets
a clean result, and finds the next thing without a tutorial (#279 is the gate; the owner's run).

- **#280 state audit** — `docs/STATE-AUDIT.md`, 258 lines: which state exists and which surface
  carries it.
- **#281 operations** — one line naming what is running and on what. Two fixes since: the command
  path now names its subject (#377, PR #379).
- **#284 discovery** — the stuck hint, error naming, and a searchable command catalogue
  (`CommandCatalog`; no command is optional, `#418`'s gated one was removed).
- **#285 the app skill** — bundled, offered at first run, install-to-enabled in one tap.
- **#226 commands screen** — grouped by what the command does, with real queued/running/done/failed
  states (PR #363).
- **#227 six-verb motion grammar** — no per-command art.
- **#224 settings split** — Being / Hearing / Voice / Presence, one Advanced disclosure each, and
  the hints hold in light mode (PR #359).
- **#225 look controls** — density, speed, trail, hue, motion scale, judged in a live preview
  inside Settings (PR #362).
- **#275 light mode** — an authored ground with measured contrast; the crawl's drawn alpha was
  fixed after the acceptance run found 2.21:1 (#372, PR #378; measured 4.13–16.36:1).
- **#329 the assistant role** — `KEYCODE_ASSIST` / side-button, focus the live call rather than
  start a second one (PR #358).
- **Entity named by the host** — onboarding adopts `data[0].id` from `/v1/models` and the field
  is display-only (#385).
- **#351/#252 `/new` redial** — the call re-arms before the server copy is deleted (PR #353).
- **#370 the share surface** — the ⌘ entry replaces `/`, "Share with agent" leads the commands
  sheet, clipboard text becomes a named file, Vox registers as a share target for
  `SEND`/`SEND_MULTIPLE`/`VIEW`, and nothing leaves the phone until SEND (PR #387).
- **#368 scroll back** — through what the agent said, by press-and-swipe, bounded history; a live
  reply does not yank the view back (PR #389).
- **#325 quiet calls** — a setting, off by default, its own switch in Hearing and **not** an Alpha
  set: priority Do Not Disturb for the length of a call only, the previous filter restored at
  hang-up unless the user changed it, recovered at app start after a crash. The on-phone check is
  a device check.
- **#251 sound cues** — the ambient/haptic cue families with the acceptance card they ship with.

## 2. Approvals — in the build; the device pass is a cut gate

- **#282 the surface** — what is being approved, why, yes/no, by voice or touch, timeout resolves
  to *no* (PR #364). The gate latches on `request_id`; `deny` is always offered.
- **#376 the arm** — a deterministic, harmless-in-effect trigger so the card can be tested at all
  (PR #390, debug-only, inert in release).
- **#404 the route flip — built and now the default.** Turns ride `/v1/runs`, which carries the
  approval notifier. A gateway that answers the admission with 404 is remembered per profile and
  falls back to `/v1/responses` (`RouteChoice`). The barge-in stops the run itself, binds the run
  id atomically, and never loses a run admitted mid-cancel. **The nine device checks in
  `docs/RUNS-ROUTE.md` are outstanding; D29 makes them a gate, not a target.**

## 3. Profiles — in the build

- **#371/#174 profiles from the host** — the switcher fills itself, every name is probed before it
  becomes usable, unknown names are marked unavailable rather than deleted, and a switch ends a
  live call (PRs #382, #384; contract in `docs/SPEC-conversational-bridge.md`).
- **VOX.md per profile — in the build**: fetched on the first call for a profile when Presence is
  on, the correct soul loaded when the profile switches, presence-gated throughout, the existing
  mirror migrated rather than lost (`VoxMirror`).
- **The switcher is a command** — **Profiles** sits under *The agent* in the commands sheet, and it
  opens as a sheet on the same scaffold the Alpha, Share and File sheets stand on. Each row is the
  agent you would be talking to: its name, then the agent name, the model and the voice under it;
  the active one carries **IN USE**. It is a picker, not an editor: profiles are configured on the
  host, so there is no add and no edit — a host that serves none says so. The header still shows
  the active profile (display only), and tapping it still opens the sheet, but the commands sheet is
  the way in. The command left Alpha on 2026-11-06 (D39) and is on for every install.
- **Per-profile settings** — a profile carries its own **voice**, **model** and **look**. The
  record gains those alongside url/key/scope; a value a profile does not own falls back to the
  device-wide one, and an existing profile inherits the device-wide values once on first load.
  A switch applies all three, visibly: the being redraws, the next utterance speaks in the new
  voice, the next turn uses the new model. The Settings rows for voice, model and look say which
  profile they apply to ("· profile home"). What stays device-wide, with the reason, is in
  `docs/PRESENCE.md`: the connection (that *is* the profile), the Alpha gate, Presence's own
  switches, and everything about the phone. Keys are encrypted per profile by `SecureStore`.

## 3b. Sessions — in the build, no gate (#437, D39)

- **Browse and resume** — the conversations the host already has, including ones started at a
  desk. `/sessions` opens a card listing what the host serves to this key, newest activity first,
  with title, source, age and the one in use marked; picking one continues that conversation and
  draws its transcript into the crawl, so the screen shows what was said instead of starting
  blank. The list is asked at the host (a profile's `/p/<name>` is stripped), a 401, a host that
  did not answer and an empty host get three different lines, and the transcript is re-read on
  resume, on `/reconnect` and after a gap — merged by message identity, never appended, so a
  reconnect cannot duplicate a conversation. A profile switch clears the adopted session. The
  device pass was the definition of done in `#437` and was made on 2026-11-06, so the **Sessions**
  set is gone and `/sessions` is on for every install.

## 6. Presence, the behaviours — in the build, behind the gate

All behind the Alpha gate; Presence and Turn-taking are selected separately:

- **#245 asides and backchannels — built, behind the Alpha *Turn-taking* set.** A recorded
  nonverbal acknowledgement while the caller talks at length: only in a mid-thought pause
  (the words so far end on "and", "so", "um"…), well short of the turn-ending silence, never
  while anything else sounds, at a capped, configurable rate (Off / Sparse / Normal; Sparse
  inside the set). Its own sound cannot reset the pause clock, so it never delays the turn.
  Needs continuous capture. English timing only. The 60-second recorded-monologue check is a
  device check.
- **#243 resume after an interruption — built, behind the Alpha *Turn-taking* set.** A voice
  barge leaves a record: what the caller heard (the frozen playback cursor), what was written
  and not heard, and whether the answer was finished. The next voice turn carries one plain
  directive — answer them first, then pick up where they cut in without repeating, or drop it
  — used once, for two minutes. A hush or hang-up leaves no mark. `event=resume-mark` and
  `event=resume-offer` log the point. The interrupt-and-resume run is a device check.
- **#242 overlap classification — built, behind the Alpha *Turn-taking* set.** The level gate
  still makes the physical cut; the words the barge carried then decide what follows. A
  listening sound ("mm-hm", "right") asks the mind to carry on from the cut without repeating;
  a word or two ("wait", "hold on") stops and listens — no turn is sent and the mark is kept;
  a sentence is a new turn carrying the #243 mark. `event=overlap class=…` per case. Third-party
  and background speech are not separated yet (no speaker enrolment in the barge path), and the
  four-class × two-level recorded matrix is a device check.
- **#217 the tuning bar — built.** `scripts/presence-session-report.py` prints a bar whose
  every row names what it measures, the events it counts, the threshold, the value and `n`
  (`docs/PRESENCE-TUNING-BAR.md`). Repeats are measured from a line hash (`h=`), without
  transcripts; the D18 turn-boundary window is measured from `boundaryMs=` on each render. The
  long Conversational run to tune against is a device session.
- **#223 the Presence transcript — built.** Not empty (the Presence path feeds it, `ea27eb7`),
  and it holds what was said: a cut reply is revised in place to what the caller heard, marked
  "— (interrupted)", instead of keeping text the voice never reached; and the transcript lives
  for the call, not the activity, so a rotation no longer empties it (memory only, never on
  disk). The 4,000-character cap is unchanged.
- **#256 the invention measurement — harness built, no device run recorded.** Sample what the
  model invents (unsourced number, unsourced fact, false action claim, repetition) across greet /
  answer / narrate, via `scripts/invention-sample.sh` → `InventionSampleTest` →
  `scripts/invention-report.py` (shape in `docs/INVENTION-MEASUREMENT.md`). Observation only.
- **A fresh pass on the directive and the rails — built.** The minimal five rules and the
  mechanical bounds, re-read against what the measurement shows; D29 dropped the no-new-numbers
  rule and kept the false-action-claim guard.

### Presence tool use (#421, D38) — in the build

- **One actor** — the phone no longer parses the caller's words; every voice turn goes to the mind,
  and the mind acts through the `phone` tool. Presence reads the registry and may not change it.
- **The mind's lane** — one MCP tool `phone` on the tailnet, with results, undo and a tier table;
  the thirteen capability groups, Off / Ask / Allow, all Off by default; the schema built from the
  live grants on every call (`docs/MCP-PHONE.md`).
- **The veto, as it shipped** — a group is Off until granted; Ask raises the phone's own card for
  **every** action, and Allow runs without one. The phone-side card for MCP calls **is** built
  (`PhoneApproval`), so Tier 2 is no longer refused: `uninstall` and `file_offer` run at Allow or
  after their card, and the unbuilt names are never advertised. **Not built:** Tier 3
  (accessibility/screen control, `docs/ACCESSIBILITY-TIER.md` — design only). The two handoff edges
  are closed: every handoff is gated on the foreground and refuses `background` with that reason
  before it resolves, ends or announces anything, and `dial` reports `dialer:"unknown"` (with
  `outcome_uncertain:true`) while its teardown is still to open the dialer, with `status` carrying
  the late `opened` / `not_opened` answer.

## 7. The Alpha gate, first run and the hardware check — in the build

- **#230 first run** — the connection, the voice and the being named in the app's own words; the
  entity's name adopted from the host and shown read-only; the hardware check's line when it
  fails.
- **The Alpha gate** — *Enable Alpha Features*, **off on a fresh install**, with six sets:
  Presence, Continuous listening, Turn-taking, Phone tools, Wake word and Digital assistant. Each
  selected on its own; the settings a set covers are dimmed and unreachable when the master is
  off. The switch sits immediately above the block of gated sections at the end of Settings, and
  every gated section belongs in that block. An
  upgrade keeps what was already running (`AlphaGate.migrate`). Presence remains the public name.
  **Sessions** and **Switching profiles** left the gate on 2026-11-06 (D39) and are on for every
  install.
- **The hardware check, two-stage** — a cheap RAM/free-memory gate at first run (8 GB bar, with a
  free-memory floor), then a real load attempt on the first call that can demote the choice. It
  advises; it never enables.

- **#222 completes here** — "Enhanced Realtime" disappears from the product: the mode picker goes,
  and what it carried is simply Presence, a layer on top of the one call.
