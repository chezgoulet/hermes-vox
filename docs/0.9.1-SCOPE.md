# 0.9.1 — everything we are building

Set 2026-11-03. This is the complete scope as it stands after the milestone re-alignment
(`docs/MILESTONES.md`, D28). It is a living document: 0.9.1 stays open until the owner signs it,
and it absorbs whatever the acceptance run and real use turn up.

## How to read this

- **In the build** — merged to `testing`, release-signed nightly available. An issue may still be
  open because it closes on the owner's device verification, not on the merge.
- **In flight** — an open pull request, under review.
- **Not built** — decided and scoped, no code yet.
- **Carried** — wanted, but not a gate; done here if achievable, otherwise closed wherever it
  closes.
- **Out** — explicitly not this release.

---

## 1. The loop and its surfaces — in the build

The release's original purpose: a stranger gives a command by voice, sees what is happening, gets
a clean result, and finds the next thing without a tutorial (#279 is the gate; the owner's run).

- **#280 state audit** — `docs/STATE-AUDIT.md`, 258 lines: which state exists and which surface
  carries it.
- **#281 operations** — one line naming what is running and on what. Two fixes since: the command
  path now names its subject (#377, PR #379).
- **#284 discovery** — the stuck hint, error naming, and a searchable command catalogue.
- **#285 the app skill** — bundled, offered at first run, install-to-enabled in one tap.
- **#226 commands screen** — grouped by what the command does, with real queued/running/done/failed
  states (PR #363).
- **#227 six-verb motion grammar** — no per-command art.
- **#224 settings split** — Being / Hearing / Voice / Presence, one Advanced disclosure each, and
  the hints hold in light mode (PR #359).
- **#225 look controls** — density, speed, trail, hue, motion scale, judged in a live preview
  inside Settings (PR #362).
- **#275 light mode** — an authored ground with measured contrast; the crawl's drawn alpha was
  fixed after the acceptance run found 2.21:1 (#372, PR #378; measured 4.13–16.36:1).
- **#329 the assistant role** — `KEYCODE_ASSIST` / side-button, focus the live call rather than
  start a second one (PR #358).
- **Entity named by the host** — onboarding adopts `data[0].id` from `/v1/models` and the field
  is display-only (#385).
- **#351/#252 `/new` redial** — the call re-arms before the server copy is deleted (PR #353).

## 2. Approvals — in the build, one gate remaining

- **#376 the arm** — a deterministic, harmless-in-effect trigger so the card can be tested at all

## 4. Share with agent — in the build

- **The file offer** — the phone stages, hashes and serves a file once on the tailnet; the agent
  fetches and verifies. 100 MB cap, five-minute expiry, `410` after the first transfer; text under
  8 KB travels inline (PR #386, and its race fixed in the same PR).
- **#370 the share surface** — the ⌘ entry replaces `/`, "Share with agent" leads the commands
  sheet, clipboard text becomes a named file, Vox registers as a share target for
  `SEND`/`SEND_MULTIPLE`/`VIEW`, and nothing leaves the phone until SEND (PR #387).
- **#327 paste** — superseded by the above; the button is gone.

## 8. First run, the gate and the check — not built

- **#230 first run, fuller** — the hardware check, the Alpha gate, the Presence default, and one
  explanation line when the check fails — plus naming the connection, the voice and the being.
- **The Alpha gate** — *Enable Alpha Features*, **off on a fresh install**, gating Presence,
  continuous capture and semantic endpointing; the settings it covers are dimmed and unreachable
  when it is off. Presence remains the public name.
- **The hardware check, two-stage** — a cheap RAM/free-memory gate at first run, then a real load
  attempt on the first call that can demote the choice. It advises; it never enables.
- **#222 completes here** — "Enhanced Realtime" disappears from the product.
